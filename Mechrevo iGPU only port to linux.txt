● GCUServicePlugin.dll 是无关的第三方

  ---
  后端服务 EC 写入分析报告

  核心问题：代码混淆

  GCUService.exe 使用了三层混淆保护：
  1. 方法体加密 — 所有方法体替换为 throw new Exception("Runtime 
  exception")，并标记 [MethodImpl(MethodImplOptions.NoInlining)]
  2. 字符串加密 — .NET #US 堆中的字符串字面量全部加密
  3. 构造器重定向 — 通过混淆委托数组
  (_0006_0007_0007_000B_0007_0009_0005_000B._0006_000A_0009_0004_0014_0017[0])
  调度

  因此无法从静态分析中获取实际的 EC 寄存器地址和写入值。

  ---
  但我们成功还原了完整的架构

  1. EC 通信双通道

  ┌─────────┬────────────────────────────┬──────────┬──────────────────────┐
  │  通道   │         设备/接口          │  实现类  │         用途         │
  ├─────────┼────────────────────────────┼──────────┼──────────────────────┤
  │ ACPI    │ \\.\VhidControl            │ AcpiCtrl │ 直接 EC              │
  │ 驱动    │ (vhidmini.sys)             │          │ 读写的底层通道       │
  ├─────────┼────────────────────────────┼──────────┼──────────────────────┤
  │ WMI     │ BIOS ACPI WMI 设备         │ WMIEC    │ 高层 EC 控制通道     │
  └─────────┴────────────────────────────┴──────────┴──────────────────────┘

  2. ACPI 驱动细节

  - 驱动: vhidmini.sys — KMDF HID mini-driver
  - 制造商: "OriginalDesign"（ODM 厂商）
  - 设备名: \Device\VhidControl → \DosDevices\VhidControl
  - IOCTL (DeviceType=40000):
    - IOCTL_GPD_ACPI_ECREAD (Func 0x922) — 读 EC
    - IOCTL_GPD_ACPI_ECWRITE (Func 0x923) — 写 EC
    - IOCTL_GPD_ACPI_CMREAD/WRITE — 命令模式读写
    - IOCTL_GPD_ACPI_MMREADB/MMWRITED — 内存映射读写
    - IOCTL_GPD_ACPI_SMART_APC_TABLE — 智能 APC 表

  3. WMI 接口方法

  - Smrw(cmd, value, ref data) — SMRW 命令，cmd: 读取=0xBB, 写入=0xAA
  - GetSetULong2(cmd, addr, offset, value, ref data) — 通用 ULong2 命令
  - WMIWriteECRAM(addr, value) / WMIReadECRAM(addr, ref data) — 直接 EC RAM 读写

  4. GPU 模式切换专用的 WMI 方法

  - WMIWriteECIGPUonlyON() — iGPU Only 模式开启
  - WMIWriteECIGPUonlyOFF() — iGPU Only 模式关闭
  - WMIGetECDGPUStatusForIGPUonly() — 获取 dGPU 状态
  - WMIGetECIGPUonlySupport() — 检查 iGPU Only 支持
  - WMIIsSupport_IGPU_Mode() — 检查 iGPU 模式支持

  5. 完整调用链

  前端 WinUI App
    → MQTT "Setting/Control" topic
      → {"Action":"IGPU_ONLY_CONNECT_RB_ON", "SetToWMIEC":"OK"}

  获取实际 EC 写入值的方法

  由于静态分析被混淆阻断，建议以下动态分析方法：

  1. ACPI DSDT 反编译 — 从 BIOS 提取 DSDT 表，找到 WMI 方法的 ASL 实现，可以看到

  方法上设断点，触发 GPU 模式切换时捕获参数值

● 提取 ACPI DSDT 并反编译 WMI 方法

  有几种方法，从简单到复杂：

  方法一：Windows 下直接提取（最简单）

  在 管理员 PowerShell 中运行：

  # 方法1: 直接从 C:\Windows\System32\acpi.sys 所在位置获取
  # Windows 会把 ACPI 表加载到注册表和内存中

  # 用 RWEverything 提取（推荐，GUI 工具）
  # 下载: https://rweverything.com/
  # 打开后点击 ACPI 选项卡，右键 DSDT → Save

  # 方法2: 用 acpidump 命令行工具
  # 来自 ACPICA 项目: https://www.acpica.org/downloads
  acpidump.exe -b -o acpidump.bin
  # 然后拆分表
  acpixtract.exe acpidump.bin

  方法二：Linux 下提取（如果你有 Linux 环境）

  # 方法1: 从 sysfs 直接读取
  sudo cat /sys/firmware/acpi/tables/DSDT > DSDT.dat

  # 方法2: 使用 acpidump
  sudo apt install acpica-tools
  sudo acpidump -o acpidump.dat
  acpixtract acpidump.dat    # 拆分出各个表

  # 反编译
  iasl -d DSDT.dat           # 生成 DSDT.dsl (可读的 ASL 源码)

  方法三：从 Windows 内存中提取（无需重启）

  在管理员 PowerShell 中：

  # 使用 Get-ACPITable 脚本（PowerShell）
  # 或者直接读取内存映射

  # 最简单的方式 - 使用 Windows 内置的 ACPI 诊断
  # 在管理员命令提示符中:
  # 这会导出所有 ACPI 表到指定目录
  mkdir C:\ACPI
  # 用 CrystalInfo 或 RWEverything 导出

  反编译后的分析

  拿到 DSDT.dsl 后，搜索关键内容：

  # 搜索 WMI 相关方法
  grep -n -i "WMIS\|wmie\|smrw\|GetSetULong\|ECRAM" DSDT.dsl

  # 搜索 EC 操作区域定义
  grep -n -i "OperationRegion\|ECOR\|ERAM\|EmbeddedControl" DSDT.dsl

  # 搜索 GPU/iGPU/dGPU 相关
  grep -n -i "IGPU\|DGPU\|DGPU.Direct\|IGPUonly\|Graphics" DSDT.dsl

  # 搜索 WMI 数据块定义
  grep -n -i "Method.*WMIS\|Method.*WMI\|Name.*WMIS" DSDT.dsl

  WMI 到 EC 映射的结构

  DSDT 中通常长这样：

  // EC 操作区域定义（关键 - 定义了 EC 寄存器映射）
  OperationRegion (ECOR, EmbeddedControl, 0x00, 0xFF)
  Field (ECOR, ByteAcc, NoLock, Preserve)
  {
      Offset(0x00),

  完整分析结果：GPU 模式切换的 ACPI 实现

  核心发现：GPU 模式切换不直接写 EC 寄存器

  通过 DSDT 反编译发现，iGPU Only 模式切换是通过 PCIe 
  热插拔（Hot-Plug）机制实现的，不是写 EC 寄存器。

  WMI 设备

  Device (AMW0)   // _HID = PNP0C14 (WMI Device), _UID = 1
      IGPM = 1    // iGPU Mode Present = 支持
      AC00 = Buffer (数据块)
          SAC0 = dword[0]  → 子命令 (0/1/2/3)
          SAC1 = dword[4]  → 功能码 (0x0300 = iGPU模式控制)

  WMI 分发路径

  OEMG 方法 (DSDT.dsl:103566):

  If (SAC1 == 0x0300) {                    // iGPU Mode Control
      If (IGPM == One) {                   // 硬件支持检查
          If (SA00 == 1)  → IGPS(1)        // iGPU Only ON
          If (SA00 == 0)  → IGPS(0)        // iGPU Only OFF (恢复Hybrid)
          If (SA00 == 2)  → DGPS()         // 查询dGPU电源状态
          If (SA00 == 3)  → return 0x55    // 不支持
      }
  }

  IGPS 方法 — 实际 GPU 切换逻辑 (DSDT.dsl:104892)

  IGPS(1) — iGPU Only ON：
  1. 检查 dGPU PCIe 插槽 (RP09) 是否已关机
  2. 如果 dGPU 在线:
     a. Notify(RP09.PXSX, 0x03)  // 发送 PCIe Eject Request 给 dGPU
     b. RP09.PXSX._PSC = 0       // 设置电源状态
     c. 等待最多 10秒 (100×100ms) 直到 _PSC == 3 (D3关机状态)
     d. 成功: IGPU = 1, Notify(RP09, 0x00)  // Bus Check 重新枚举
     e. 超时: IGPU = 2
  3. 如果 dGPU 已经离线:
     RP09._PS3()  // PCIe 插槽断电
     IGPU = 0xAA

  IGPS(0) — iGPU Only OFF（恢复 Hybrid）：
  1. 如果 dGPU 在线: RP09._PS3() 断电, IGPU = 0xAA
  2. 如果 dGPU 离线:
     IGPU = 0
     Notify(RP09, 0x00)       // Bus Check - 重新扫描 PCIe
     Notify(RP09.PXSX, 0x00)  // Bus Check - 重新枚举 dGPU 设备

  EC 寄存器映射 (内存映射 0xFE410000)

  GPU 相关的 EC 寄存器是状态监控用，不是模式切换的控制寄存器：

  前端: {"Action":"IGPU_ONLY_CONNECT_RB_ON", "SetToWMIEC":"OK"}
    → MQTT topic "Setting/Control"
      → GCUService MySettingManager.Receive()
        → UserSetIGgpuONLYConnectionSwitch(status, writeToWMIEC)
          → WMIEC.WMIWriteECIGPUonlyON()

  结论

  IGPU_ONLY_CONNECT_RB_ON 不向 EC 写入任何特定寄存器值。 它通过 WMI 调用 ACPI
  方法 IGPS(1)，该方法使用标准 PCIe 热插拔通知（Notify 事件码 0x03=Eject,
  0x00=Bus Check）来控制 dGPU 的上电/断电，实现 iGPU Only 模式切换。dGPU
  物理连接在 PCIe Root Port RP09 上，通过 PCIe 电源管理（D0/D3 状态）控制开关。

     GPU Mode Switching Script for Linux (Mechrevo)

     Context

     Reverse-engineered the Mechrevo Control Center's GPU mode switching. The
     DSDT ACPI table reveals that iGPU Only mode is implemented via PCIe
     hot-plug on the dGPU slot (RP09), not by writing EC registers. This script
     replicates that behavior on Linux.

     Implementation: gpu-switch.sh

     Single bash script with 3 commands:

     Commands

     - gpu-switch.sh status — show current GPU mode (iGPU only / Hybrid)
     - gpu-switch.sh igpu — switch to iGPU Only (power off dGPU via PCIe
     hot-remove)
     - gpu-switch.sh hybrid — switch to Hybrid mode (rescan PCIe to bring back
     dGPU)

     Logic

     Status check:
     - lspci | grep -i nvidia to detect if dGPU is present
     - Read /sys/bus/pci/devices/<dGPU>/power/runtime_status for power state

     iGPU Only (igpu command):
     1. Find dGPU PCIe address via lspci -D | grep -i nvidia | head -1
     2. Find parent PCIe port (root port)
     3. Check if any process is using the GPU (lsof or fuser)
     4. Unload nvidia-open modules: modprobe -r nvidia_drm nvidia_modeset 
     nvidia_uvm nvidia
     5. Remove dGPU from PCIe bus: echo 1 > /sys/bus/pci/devices/<dGPU>/remove
     6. Optionally power off the PCIe root port: echo 1 > 
     /sys/bus/pci/devices/<rootport>/remove
     7. Verify removal with lspci

     Hybrid mode (hybrid command):
     1. echo 1 > /sys/bus/pci/rescan
     2. Wait for dGPU to appear (poll lspci)
     3. Load nvidia-open modules: modprobe nvidia
     4. Verify with lspci | grep nvidia

     Safety

     - Root check
     - Display manager check (warn if X/Wayland is using the GPU)
     - Dry-run mode (--dry-run)
     - Confirmation prompt before destructive operations

     File

     - Create: /home/ubuntu/claude/windows_power/gpu-switch.sh
     - Single file, no dependencies beyond standard Linux tools (lspci,
     modprobe, sysfs)
